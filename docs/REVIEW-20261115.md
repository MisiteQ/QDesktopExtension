# QDesktopExtension 代码审查报告（2026-11-15）

审查范围：`ConfigModel / MainForm / AppHost / CaptureWorker / AccessControl / SimpleHttpServer /
StreamServer / DisplayCapture / StreamPipeline / VirtualScreen / Program / TrayApp / Resources/index.html /
install.ps1 / install-vdd.ps1 / uninstall.ps1 / build-release.ps1`

## 一、本轮已确认并修复的真实缺陷

| # | 位置 | 问题 | 影响 | 处理 |
|---|------|------|------|------|
| 1 | `StreamServer.BuildMonitorsJson()` | 追加"虚拟桌面"汇总项时少一个逗号，输出 `}{` 相连 | `/status` 返回非法 JSON，任何解析它的程序都会失败 | 补 `if (monitors.Count > 0) sb.Append(',');` |
| 2 | `StreamPipeline` | `_jpegBuf` 用 `Marshal.AllocHGlobal` 分配（1080p ≈8MB），从不释放 | 每次"保存并重启服务"泄漏一块非托管内存，长时间反复重启会把进程内存吃光 | 新增 `Dispose()`：停 worker、释放 `_jpeg`/`_jpegBuf`（FreeHGlobal）、释放 `_muxer`/`_virtual`；在 `AppHost.RunLoop` 与 `Program.RunConsole` 的 finally 中调用 |
| 3 | `MainForm` | `StartPosition = CenterScreen` | 接了虚拟显示器后窗口被摆到扩展屏上（实测窗口 x=4124，截图全白），用户以为程序没启动 | 改 `Manual`，按 `Screen.PrimaryScreen.WorkingArea` 居中 |
| 4 | `StreamServer` 重发 auth_ok | ping 触发的 auth_ok 无节流 | 客户端持续 ping 时被反复灌 `auth_ok`，弱网下加剧拥塞 | `ClientState.LastAuthOkAt`，距上次 >5s 才补发 |
| 5 | `install.ps1` 回写配置 | 用 `UTF8Encoding($true)` 写 BOM | 配置多出一个 BOM，虽然能读，但污染文件、第三方工具解析易出错 | 改 `$false`；同时把 `driver\` 一起复制进安装目录，方便日后本地重装驱动 |
| 6 | `ConfigModel` / 配置落盘 | 用户上次测试把 `UseVirtualScreen=true`、`CaptureMonitor=1` 写进配置 | 有真实第 2 块屏时仍去采集"软件扩展屏"，采集一帧 **165ms**，帧率被压到 **6fps**，手机端看起来就是卡死/像黑屏 | 已把运行配置切回真实显示器（`UseVirtualScreen=false`、`CaptureMonitor=1`），实测恢复 **30fps / 1920×1080 / 采集<10ms** |

## 二、发现但暂未改动（低危 / 需产品决策）

1. **`/windows`、`/caps-result` 未鉴权**：局域网内任何人可读到本机窗口标题列表（信息泄露面小，但确实存在）。建议后续加 token 校验。
2. **`AccessControl.Forget(ip)` 按 IP 清理**：同一 NAT 后面多台设备共享公网 IP 时会误踢其它连接。建议改成按连接对象清理。
3. **`DisplayCapture.CreateResources` 失败路径**：异常时 `screenDc` 未释放，反复失败会累积 GDI 句柄。建议加 try/finally。
4. **单实例行为**：第二个实例只弹"已在运行"提示，不会唤起已有面板。体验上建议改成唤起已有窗口（可用 `FindWindow` + 自定义消息）。
5. **`UdpStreamer` / `TransportMode` / `ClientMaxBitRate`**：代码里保留但面板已不暴露，实际走 TcpOnly。属于"留后路"的死配置，建议后续要么接上、要么删掉。
6. **兼容（JPEG）通道分辨率固定 960×432@25fps**：不支持 WebCodecs 的浏览器（如 MIUI 自带浏览器）只能走这条通道，画面偏软。若要做清晰度，需要给它加"高分辨率低帧率"档。

## 三、设置面板重做（已落地）

- 结构：深色标题栏（标题 + 副标题 + 状态行 + 启动/停止按钮）→ 访问地址卡片 → 三页 Tab（显示模式 / 画质 / 其他）→ 底部消息 + 「保存配置」「保存并重启服务」。
- 删掉的无效项：UDP 端口、传输方式、x264 预设、单客户端带宽、笔压注入、关键帧间隔、编码线程数、原始 BindAddress 文本框、以及原来的"配置扩展屏…"对话框。
- 交互：关闭窗口三选一（询问 / 只关面板 / 退出并停服务）；托盘继续串流；开机自启。

## 四、客户端（浏览器）改动

- **全屏**：不再单靠 `requestFullscreen()`。改为"沉浸模式"主路径——画面铺满视口、其它按钮 3 秒后淡出；原生全屏成功则顺带启用，并按 `screen.orientation` 锁当前方向；若方向角变化到 180° 附近，`#stage` 加 `.flip180` 反向补偿，解决"点全屏画面转 180° 且没全屏"。
- **锁屏 / 屏幕关闭同步**：Windows 锁屏后切到安全桌面，任何截屏接口（DXGI / BitBlt）都拿不到画面，所以改为"检测 + 提示"：
  服务端用 `WTSQuerySessionInformation(WTSSessionInfoEx)` + `OpenInputDesktop` 双重判断（锁屏、屏幕关闭、独占全屏都算），
  状态变化时广播 `{"type":"lock","locked":true/false}`；客户端自己也兜底——超过 3 秒没有新帧就盖一层
  "电脑已锁屏 / 屏幕已关闭　解锁或点亮屏幕后画面会自动恢复，不用重新连接"，画面恢复后自动撤掉，不会停在最后一帧。
- **USB 数据线直连**：新增 `UsbBridge`，用 `adb reverse tcp:8767 / tcp:8765` 把手机上的 127.0.0.1 映射到电脑，
  手机浏览器打开 `http://127.0.0.1:8767/` 即走数据线；拔线自动回退局域网。面板新增「连接方式」页：
  局域网 / USB / 两种都允许，并实时显示检测状态与「重新检测 USB」。
- 页面标题、产品名统一为 QDesktopExtension。

`VirtualDisplayStreamer` → `QDesktopExtension`：命名空间、程序集名、exe 名、互斥体、注册表 Run 值、卸载项、安装目录、
桌面/开始菜单快捷方式、窗口标题、网页标题、脚本与文档全部改完；`VirtualDisplayStreamer.csproj` 重命名为
`QDesktopExtension.csproj`，清理 obj 后重新编译通过（0 error）。

## 六、结论

当前主线（复制屏幕 / 扩展屏 / 浏览器接入 / 输入回传）可正常跑通；本轮修复集中在会导致"假死、卡顿、非法规 JSON、内存泄漏"的问题上。上面第二节的 6 条属于加固项，不影响现在使用。
